# Git Diff Commands

Recipes for scoping, filtering, and inspecting branch or commit changes before generating comments.

## 1. Establish the comparison range

Always prefer the merge base so unrelated upstream commits are excluded.

```bash
git fetch origin
BASE=$(git merge-base origin/main <TARGET_BRANCH>)
echo "$BASE"
```

If the repository uses a different default branch, substitute `origin/main` with `origin/master`, `origin/develop`, etc.

## 2. Summarize the change set

```bash
git diff --stat "$BASE"..<TARGET_BRANCH>
git diff --name-status "$BASE"..<TARGET_BRANCH>
```

`--name-status` returns status letters you can filter on:

- `A` added
- `M` modified
- `D` deleted — never modify these files
- `R` renamed
- `C` copied

## 3. Filter by allowed file types

```bash
git diff --name-only "$BASE"..<TARGET_BRANCH> -- '*.cs' '*.razor' '*.js' '*.ts' '*.sql'
```

Or exclude by path:

```bash
git diff --name-only "$BASE"..<TARGET_BRANCH> -- . \
  ':(exclude)*.lock' \
  ':(exclude)package-lock.json' \
  ':(exclude)dist/**' \
  ':(exclude)node_modules/**'
```

## 4. Inspect a single file's diff

```bash
git diff "$BASE"..<TARGET_BRANCH> -- path/to/file.cs
git diff -U10 "$BASE"..<TARGET_BRANCH> -- path/to/file.cs   # wider context
```

## 5. Work from specific commits

```bash
git show --stat <COMMIT_ID>
git show <COMMIT_ID> -- path/to/file.cs
git diff <COMMIT_ID>~1 <COMMIT_ID>
```

Multiple comma-separated commit IDs:

```bash
git show --stat AAA1
git show --stat BBB2
git show --stat CCC3
```

To treat a range of commits as one unit:

```bash
git diff <FIRST_COMMIT>~1 <LAST_COMMIT>
```

## 6. Detect renames and copies

```bash
git diff --find-renames --find-copies --name-status "$BASE"..<TARGET_BRANCH>
```

Pure renames with no content change should normally be skipped.

## 7. Detect binaries and generated files

```bash
git diff --numstat "$BASE"..<TARGET_BRANCH> | awk '$1=="-" && $2=="-"'
```

Rows with `-` for both additions and deletions are binary. Skip them.

Generated files are usually identifiable by path or header. Common signals:

- Path contains `generated`, `auto`, `dist`, `build`, `out`, `obj`, `bin`.
- Header contains `DO NOT EDIT` or `<auto-generated>`.
- Filename matches `*.designer.cs`, `*.g.cs`, `*.generated.ts`.

## 8. Confirm a file still exists at the target

```bash
git cat-file -e <TARGET_BRANCH>:path/to/file.cs && echo "exists"
```

Do not attempt to add comments to files deleted on the target branch.

## 9. Verify no branch exists before reporting an error

```bash
git rev-parse --verify <TARGET_BRANCH>
git rev-parse --verify <BASE_BRANCH>
```

If either fails, report the issue and stop without modifying files.

## 10. Re-check the insertion point before applying

If the file may have changed since the preview:

```bash
git diff -- path/to/file.cs
```

Re-read the file and revalidate the line number before inserting the comment.
